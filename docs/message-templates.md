# 문자 · 메모 템플릿 카탈로그

PPTX의 "Mind flow 활용/추가 활용" 지점(슬라이드 6–8, 14–16, 20)에서 도출한 템플릿 목록이다.
**결정 #2에 따라 이번 범위는 문구 "생성"까지다** — 아래 각 템플릿은 `MessageLog`/`EmrMemoLog`
(`data-model.md` §8)로 저장되고, 발송은 사람이 수동으로 복사해 보낸다. `sentAt`은 Phase 6 이전엔 채워지지 않는다.

플레이스홀더 표기는 `config/README.md`의 관례(`{이름}`)를 따른다.

## 1. `pre_visit_intro` — 연구 안내 문자 (슬라이드 6)

| 항목 | 내용 |
|---|---|
| 트리거 | 인롤 확정 직후, V1 일정 조율 전 |
| 채널 | 문자(유선 연락 병행) |
| 구성요소 (원문 순서 그대로) | ① 무작위 배정 안내 ② 참여 여부 재확인 ③ 11주간 진행 일정 간략 안내(사전평가–중간평가–종료평가–추적검사) ④ V1 동의서 작성 및 사전검사 일정 조율, 예상 소요 시간 안내 |
| 플레이스홀더 | `{subjectName}`, `{studyTitle}`, `{armLabel}`(무작위 배정 결과 — 배정 후 발송 시), `{v1CandidateDates}`, `{v1DurationMinutes}` |
| 비고 | 슬라이드 6은 문구 자체보다 "포함해야 할 내용"만 명시 — 최종 문구는 연구팀 검수 필요(`open-questions.md`) |

## 2. `pre_visit_reminder` — 방문 전 리마인드 (슬라이드 6, 8)

| 항목 | 내용 |
|---|---|
| 트리거 | 방문 하루 전(자동 발송 대상이었던 기능, 이번 범위는 생성만) |
| 채널 | 문자 |
| 플레이스홀더 | `{subjectName}`, `{visitLabel}`(예: 사전평가), `{visitDate}`, `{visitTime}`, `{visitDurationMinutes}`, `{location}` |
| 비고 | 슬라이드 7: "피험자 입력란 생성 + 진행일시, 무작위 배정 결과 추가입력 → 문자 멘트 생성 + 보내기 기능" — 입력 필드는 `SubjectVisit.scheduledDate`에서 병합 |

## 3. `assessment_intro` — 임상척도 사전 안내 설명문 (슬라이드 8, 원문 그대로 탑재)

트리거: 사전평가(V1) 전, 첫 척도 시행 안내 화면. **원문 전체를 그대로 사용**(의역 금지 — 기존
config 관례와 동일):

> 연구 참여 과정에서 현재의 신체 증상, 기분 및 불안, 건강에 대한 걱정, 삶의 질 등을 알아보기 위한
> 여러 설문검사를 시행합니다. 각 검사는 현재 상태를 파악하고 치료 또는 교육 프로그램 참여 전후의
> 변화를 확인하기 위한 목적으로 사용됩니다.
>
> - **PHQ-15**: 현재 경험하고 있는 신체 증상의 정도를 평가합니다.
> - **SSD-12**: 신체 증상과 관련된 생각, 감정 및 행동 특성을 평가합니다.
> - **BDI-II**: 우울 증상의 정도를 평가합니다.
> - **BAI**: 불안 증상의 정도를 평가합니다.
> - **ASI-3**: 불안으로 인해 나타나는 신체적·심리적 감각에 대한 민감성을 평가합니다.
> - **WHOQOL-BREF**: 신체적·심리적 건강, 사회적 관계 및 생활환경 등을 포함한 전반적인 삶의 질을
>   평가합니다.
> - **K-HAQ**: 건강에 대한 걱정이나 염려의 정도를 평가합니다.
>
> 각 설문은 정답이 있는 검사가 아니며, 현재 자신의 상태에 가장 가까운 응답을 선택하시면 됩니다.
> 설문 결과는 연구 참여 전후의 증상 및 삶의 질 변화를 확인하고, 인지행동치료의 효과를 평가하기
> 위한 연구자료로 활용됩니다.
>
> 연구 종료 후에는 연구와 관련하여 시행한 검사 결과를 참여자가 이해하기 쉽도록 해석 및 설명과
> 함께 제공할 예정입니다. 연구 결과는 참여자의 개인정보가 확인되지 않도록 처리하여 연구 목적으로
> 활용됩니다.

플레이스홀더 없음(정적 텍스트). config 스키마상 `study.assessmentIntroText` 필드로 저장.

## 4. `control_arm_weekly_material` — 대조군 주간 디지털 교육자료 (슬라이드 16)

| 항목 | 내용 |
|---|---|
| 트리거 | 대조군 배정자, 개입 기간(11주) 매주 |
| 채널 | 카카오톡(비대면) |
| 비고 | PPTX에 실제 자료 콘텐츠/문구가 없음 — 콘텐츠 소스 확인 필요(`open-questions.md`). 템플릿 구조만 선반영: `{weekNumber}`, `{materialLink}` |

## 5. `intervention_arm_reminder` — 실험군 CBT 방문 리마인드 (슬라이드 16)

| 항목 | 내용 |
|---|---|
| 트리거 | 대면 CBT 방문 하루 전, 개입 기간 매주 |
| 채널 | 문자 |
| 플레이스홀더 | `{subjectName}`, `{sessionNumber}`(1~11주차), `{visitDate}`, `{visitTime}` |

## 6. EMR 메모 템플릿 (슬라이드 15, 원문 포맷 그대로)

인롤/종료 시점에 EMR 환자메모에 기재하는 정형 문구. `EmrMemoLog`에 `eventType`×`armKey`로 4종 생성.

| eventType | armKey | 템플릿 |
|---|---|---|
| `enrollment_start` | `intervention` | `연구 참여 시작: {consentDateYYMMDD}) SSD CBT 연구 등록(CBT 시작일 - 담당자, 일정)` |
| `enrollment_end` | `intervention` | `참여 종료: {endDateYYMMDD}) SSD CBT 참여 종료(실험군)` |
| `enrollment_start` | `control` | `연구 참여 시작: {consentDateYYMMDD}) SSD CBT 연구 등록(대조군)` |
| `enrollment_end` | `control` | `참여 종료: {endDateYYMMDD}) SSD CBT 참여 종료(대조군)` |

`{consentDateYYMMDD}` / `{endDateYYMMDD}`는 PPTX 표기(`YYMMDD`)를 그대로 따른다.

## 7. `visit_schedule_share` — 피험자별 일정표 (슬라이드 7, 10, 14)

문자/메모는 아니지만 같은 "생성 후 수동 전달" 패턴이라 함께 카탈로그화한다.

| 항목 | 내용 |
|---|---|
| 트리거 | 사전평가 직후, `Subject.consentDate` + `VisitScheduleTemplate` 확정 시 |
| 출력 형식 | 인쇄용 레이아웃(배포용 Print) 또는 이미지 내보내기(전송용) |
| 내용 | 방문별(`사전-중간6주-사후11주-추적23주`) 예정일 + 방문별 환자 안내사항(임상척도 설명, fNIRS 유의사항 — 슬라이드 10) |

## 8. 결과보고서 전송 문구 (슬라이드 20) — SSD_CBT 비대상, 타 연구용으로 설계만 선반영

| 항목 | 내용 |
|---|---|
| 채널 | 피험자: 카카오톡 / 교수님: 이음톡 |
| 비고 | PPTX에 정확한 문구 포맷 없음 — `ReportRecord` 생성 시점에 자동 채워지는 첨부 안내문 정도로 최소 템플릿만 Phase 5에서 설계, 문구는 연구팀 확인 필요 |
