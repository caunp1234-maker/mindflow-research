# 척도 config 확장안

기존 `config/assessments.json`(PHQ-9, GAD-7)의 스키마를 그대로 계승해 SSD_CBT 척도 7종을 추가하기
위한 설계안이다. 실제 JSON 작성과 `test-vectors.json` 확장은 **Phase 2**에서 수행하고, 이 문서는
그때 필요한 스키마 변경점과 척도별 특이사항을 미리 정리해 둔다. 문항 원문 출처는
`설문지_ver1.1_260422_전체 취합본.pdf`, 채점 기준 출처는 `PHQ.docx`이며, 쪽수는 PDF 기준이다.

## 1. 스키마에 추가해야 하는 것

기존 스키마(`assessments.<id>.scoring/severityBands/clinicalCutoff/subscales/safetyPathway/
interpretationTemplates`, `config/README.md` 참조)로 PHQ-9/GAD-7은 충분했지만, 7종 중 3개는
스키마 확장이 필요하다.

| 확장 항목 | 필요한 척도 | 내용 |
|---|---|---|
| `scoring.method: "mean"` | K-HAQ | 기존엔 `"sum"`만 존재. 합산 후 문항 수로 나누는 평균 채점 방식 추가 필요 (§3 참조) |
| `items[].responseVariants` | BDI-II | 16·18번 문항의 1a/1b, 2a/2b, 3a/3b 응답지를 다른 문항과 같은 UI로 렌더링하되, 점수는 표시 라벨과 무관하게 숫자 그대로 채점 (§3 참조) |
| `domains[]` 블록 (신규) | WHOQOL-BREF | 문항→도메인 매핑 + 원점수(4–20) → 0–100 변환 공식. 기존 `subscales[]`는 절단점 판정용이라 변환식을 못 담음 — 별도 블록 필요 (§3 참조) |
| 엔진 처리 순서에 "역채점" 단계 추가 | WHOQOL-BREF | `items[].reverse`는 이미 스키마에 있으나(PHQ-9/GAD-7은 전부 `false`라 미사용), 엔진의 "판독 엔진 처리 순서"(`config/README.md` §하단)에 실제 역채점 스텝이 없음 — 총점 계산 전에 추가 필요 |
| `safetyPathway` 재사용 | BDI-II | 기존 PHQ-9 전용 구조를 그대로 재사용 가능 (§2) |

스키마 자체의 하위호환은 유지된다 — PHQ-9/GAD-7 정의는 수정 없이 그대로 동작해야 한다.

## 2. 척도별 정의 개요

| id(제안) | fullName | 문항수 | 응답척도 | 총점범위 | 채점방식 | 회상기간 | 안전경로 | PDF 쪽 |
|---|---|---|---|---|---|---|---|---|
| `phq15` | 신체증상척도(PHQ-15) | 15 | 0–2 | 0–30 | sum | 지난 4주 | 없음 | 3 |
| `ssd12` | 신체증상장애-B 진단기준 척도(SSD-12) | 12 | 0–4 | 0–48 | sum | **미기재 — 확인 필요** | 없음 | 4 |
| `bdi2` | Beck 우울척도 2판(BDI-II) | 21 | 0–3 | 0–63 | sum | 오늘 포함 지난 2주 | **9번 문항(자살사고)** | 5–7 |
| `bai` | Beck 불안척도(BAI) | 21 | 0–3 | 0–63 | sum | 오늘 포함 지난 1주 | 없음 | 8 |
| `asi3` | 한국판 불안민감성 지표-3(ASI-3) | 18 | 0–4 | 0–72 | sum | 명시 없음(상시 경향 질문) | 없음 | 9–10 |
| `whoqol_bref` | 한국어판 WHO 삶의 질 척도(WHOQOL-BREF) | 26 | 문항별 1–5 | 0–100* (도메인 변환) | domain transform | 지난 2주 | 없음 | 11–13 |
| `khaq` | 한국판 건강불안 질문지(K-HAQ) | 21 | 0–3 | **0–3(평균)** | mean | 명시 없음 | 없음 | 14 |

절단점/심각도 구간은 `PHQ.docx` 표를 그대로 옮긴다(§4).

## 3. 척도별 특이사항 (엔진 설계에 직접 영향)

### PHQ-15 (`phq15`)
가장 단순 — 기존 PHQ-9와 동일 패턴(`sum`, 결측 비례환산 로직 재사용 가능). id는 `phq9`와 구분되게
`phq15`로 하되, config 주석에 "PPTX/PDF 표기는 '신체증상척도'이며 PHQ-15로 통칭됨"을 남긴다.

### SSD-12 (`ssd12`)
표준 채점(단순 합산, 0–48)과 일치. **회상기간이 원문에 없다** — PHQ-15가 "지난 4주"이므로 동일
지시문을 공유하는지, 아니면 회상기간 없이 "현재 상태"를 묻는지 임상 검토자 확인이 필요
(`open-questions.md`).

### BDI-II (`bdi2`)
- 16번(수면)·18번(식욕) 문항은 응답 라벨이 `0, 1a, 1b, 2a, 2b, 3a, 3b` 7개지만 점수는 `0,1,1,2,2,3,3`
  으로 숫자만 채점에 들어간다. `items[].responseVariants`로 라벨↔점수 매핑을 명시하고, UI는 7지선다,
  채점 엔진은 숫자값만 사용.
- 9번 문항(자살사고, "나는 자살 같은 것을 생각하지 않는다" ~ "나는 기회만 있으면 자살할 것이다",
  0–3점)은 기존 PHQ-9 `safetyPathway` 구조를 그대로 재사용한다. PHQ-9는 "9번 ≥1이면 발동"이었는데
  BDI-II는 0–3 4단계 전부가 위험도를 담고 있어 `levels[]`를 4단계(0/1/2/3)로 재정의해야 한다.
  **위험 단계별 권고 동작 문구는 PHQ-9와 마찬가지로 임상 검토자 승인 전 초안으로 둔다.**

### BAI (`bai`)
특이사항 없음 — PHQ-15와 같은 단순 `sum` 패턴.

### ASI-3 (`asi3`)
PHQ.docx에 "별도 공식 중증도 기준 없음, 점수가 높을수록 불안민감성이 높음"만 명시되어
`severityBands` 없이 `clinicalCutoff`도 없이 총점만 표기하는 구조로 설계한다. 국제 표준 ASI-3는
신체적/인지적/사회적 우려 3개 하위척도가 있지만 **본 프로젝트 소스 문서에는 하위척도 문항 매핑이
없어 1차 구현에서는 총점만 산출**하고, 하위척도는 확인 후 `subscales[]`로 추가한다.

### WHOQOL-BREF (`whoqol_bref`)
가장 복잡한 척도.
- 문항별 응답 척도의 의미 방향이 다르다(예: 1번 "삶의 질 평가"는 5=매우 좋음이지만, 3번 "통증으로
  인한 방해"는 5=매우 많이 그렇다=나쁨). 표준판 기준 3, 4, 26번 등이 역채점 대상으로 알려져 있으나,
  본 프로젝트 소스 문서에는 도메인 구성과 역채점 문항 목록이 명시돼 있지 않다.
- PHQ.docx의 "0–100*" 별표는 원점수 합산이 아니라 **도메인별 변환 점수**(WHO 표준: 도메인 원점수
  4–20 → `(원점수−4)×(100/16)`으로 0–100 변환)를 가리키는 것으로 추정된다.
- 신규 `domains[]` 스키마 블록 제안:
  ```
  domains: [
    { key, label, items: [...], reverseItems: [...], rawRange: [min,max], transformTo0to100: true }
  ]
  ```
- **도메인-문항 매핑과 역채점 문항 목록은 이 프로젝트의 두 소스 문서만으로 확정할 수 없다** —
  임상 검토자가 한국어판 WHOQOL-BREF 매뉴얼로 확인 후 채워야 한다(`open-questions.md`).

### K-HAQ (`khaq`)
- 하위요인 4개가 원문에 명시되어 있어 그대로 `subscales[]`로 이식 가능:
  - `health_worry`(건강염려와 집착): 1,2,3,4,6,7,8,9,10,11,18번 (11문항)
  - `life_interference`(삶에 대한 방해): 19,20,21번 (3문항)
  - `fear_of_illness_death`(병과 죽음에 대한 공포): 14,15,16,17번 (4문항)
  - `reassurance_seeking`(안심추구 행동): 5,12,13번 (3문항)
- **총점 채점 방식이 다른 6개 척도와 다르다.** PHQ.docx의 총점 범위가 "0–3"으로 돼 있는데 21문항
  합산이면 0–63이어야 하므로, K-HAQ는 **전체 21문항 응답의 평균**으로 총점을 낸다고 해석했다.
  `scoring.method: "mean"`(§1) 도입이 이 척도 때문에 필요하다. 하위요인별 점수도 각 하위요인
  문항의 평균으로 낼지, 합산으로 낼지는 PHQ.docx에 명시가 없어 확인 필요.
- 역채점 문항 없음(원문에 명시: "채점방법은 역채점 문항이 없으므로 각 문항들의 점수를 더하면
  총점이 산출되는 방식").  ※ 이 문장은 "더하면"이라고 돼 있어 합계 방식을 시사하는 것처럼 보이지만
  바로 위 표의 총점 범위는 "0–3"이라 상충한다 — **이 모순은 반드시 임상 검토자에게 확인**해야 하며,
  확인 전까지 `clinicalApproval.status: "pending"`을 유지한다.

## 4. 절단점 · 심각도 구간 (PHQ.docx 원문)

| 척도 | 구간 | 해석 |
|---|---|---|
| PHQ-15 | 0–4 / 5–9 / 10–14 / 15+ | 최소한 / 경미 / 중등도 / 중증 신체화 증상 |
| SSD-12 | 0–28 / ≥29 | 낮은 심리적 부담 / SSD 관련 심리적 부담 높음(SSD 선별 cutoff) |
| BDI-II | 0–13 / 14–19 / 20–28 / 29–63 | 정상·최소 / 경도 / 중등도 / 고도 우울 |
| BAI | 0–7 / 8–15 / 16–25 / 26–63 | 정상·최소 / 경도 / 중등도 / 고도 불안 |
| ASI-3 | 없음 | 점수가 높을수록 불안민감성 높음 |
| WHOQOL-BREF | 없음 | 점수가 높을수록 삶의 질 높음 |
| K-HAQ | 0–<1 / 1–<2 / 2–3 | 경도~중등도 / 중등도~중증 / 중증~매우 중증 기능장애 |

## 5. Phase 2에서 할 일 (요약)

1. 위 스키마 확장 3종(§1)을 `config/README.md`에 반영하고 판독 엔진에 구현
2. 7개 척도 정의를 `assessments.json`에 추가, 문항 원문은 PDF 그대로 옮김(의역 금지)
3. `clinicalApproval.status: "pending"` 유지, 미확정 항목(§3의 굵게 표시된 부분)은 `*Source` 필드에
   "확인 필요"로 명시
4. `test-vectors.json`에 척도별 경계값·결측·안전 경로 케이스 추가 (K-HAQ는 평균 채점 경계값 특히 중요)
